# AI Financial Coach 2.0 — Multi-Agent Reliability Enhancement

## Overview

This project extends the original AI Financial Coach built with Google Agent Development Kit (ADK).

The original application contains three specialized agents:

1. **BudgetAnalysisAgent** — Analyzes income and spending patterns.
2. **SavingsStrategyAgent** — Generates savings strategies.
3. **DebtReductionAgent** — Creates debt repayment plans.

The objective of this technical challenge was to improve the reliability of the existing multi-agent framework without changing the core responsibilities of the original agents.

## My Contributions

### 1. FinancialAuditAgent — Fourth AI Agent

Added a fourth agent to the Google ADK `SequentialAgent` workflow.

It reviews the recommendations generated by the original agents and identifies:
- Conflicting financial recommendations.
- Unrealistic savings targets.
- Debt repayment strategies that ignore available cash flow.

### 2. Financial Validation Layer

Added `financial_validator.py`, a deterministic Python component that independently checks:

- Expense totals against the original CSV data.
- Debt totals against the user's input.
- Monthly available cash flow.
- Savings feasibility.
- Invalid or inconsistent financial values.

The validation layer reports `PASS`, `WARNING`, or `FAIL`.

### 3. Safe Financial Recommendation

Added a post-audit component that calculates an affordable savings ceiling from available cash flow.

When the user's cash flow is negative, the application recommends prioritizing deficit reduction rather than allocating additional money to savings.

### 4. Local LLM Integration — Ollama

Integrated Qwen 2.5 3B through Ollama to run the four agents locally.

The `ollama_structured_llm.py` adapter enforces Pydantic JSON schemas, reducing invalid structured-output responses and removing dependence on external API quotas during local execution.

### 5. Automated Evaluation

Created `evaluate_guardrail.py` to evaluate the validation layer using 12 predefined financial scenarios.

**Result: 12/12 scenarios passed their expected checks.**

This is a test-suite success rate, not a measured 10% performance improvement over the original application.

## Architecture

```text
Financial CSV + Income + Debt Information
                  |
                  v
           Google ADK
          SequentialAgent
                  |
          BudgetAnalysisAgent
                  |
          SavingsStrategyAgent
                  |
          DebtReductionAgent
                  |
        FinancialAuditAgent (NEW)
                  |
                  v
       Financial Validation Layer
                  |
                  v
       Safe Financial Recommendation
                  |
                  v
        Streamlit Dashboard
```

All four LLM agents use Ollama for local structured generation in Live mode.

## Installation

**Requirements:** Python, Ollama, and the Qwen 2.5 3B model.

Download the local model:

```bash
ollama pull qwen2.5:3b
```

Start the Ollama server:

```bash
ollama serve
```

Create and activate a Python virtual environment, then install the dependencies:

```bash
python -m venv .venv
```

On Windows:

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Create a `.env` file from `.env.example` with:

```env
OLLAMA_MODEL=qwen2.5:3b
OLLAMA_URL=http://localhost:11434
```

Start the application:

```bash
streamlit run ai_financial_coach_agent.py
```

**Note:** Ollama must be running locally. No external API key is required for the Ollama Live mode.

## Testing

## Live Demonstration — Example

One live test used these financial inputs:

| Input | Amount |
|---|---:|
| Monthly income | $3,000 |
| Monthly expenses | $3,900 |
| Minimum debt payment | $50 |
| Available cash flow | -$950 |

The Savings Strategy Agent generated $2,700 in suggested savings allocations.

The FinancialAuditAgent identified that the recommendations were inconsistent with the user's situation.

The deterministic validation layer independently flagged the savings as unaffordable.

The Safe Financial Recommendation component calculated an affordable savings ceiling of $0 and advised prioritizing deficit reduction.

This illustrates why structurally valid LLM outputs still need independent financial validation.

## Technologies

Python, Google ADK, Streamlit, Ollama, Qwen 2.5 3B, Pydantic, Pandas and Plotly.

## Limitations

- LLM-generated recommendations can contain numerical and reasoning errors.
- The validation layer detects selected inconsistencies but does not guarantee the correctness of all financial advice.
- The affordable savings ceiling is a cash-flow-based estimate, not a comprehensive personal financial assessment.
- Local LLM execution speed depends on hardware.
- This is an educational prototype, not professional financial advice.
